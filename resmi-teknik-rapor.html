YÖNETİM KURULU VE TEKNİK ÇALIŞMA GRUBUNA TEZKERE

Halen tekil cihaz hafızasında (MMKV/Zustand) yerel döngüyle çalışmakta olan Business Bank simülasyon oyunumuzun; eşzamanlı yüz binlerce kullanıcının gerçek zamanlı alım-satım yapabildiği, ortak bir makroekonomik para arzına (M2) bağlı olarak enflasyon ve deflasyon üreten, sabit lot kısıtlı hisse senedi piyasasını ve tekil gayrimenkul mülkiyetini barındıran merkezi bir MMO (Devasa Çok Oyunculu) Finansal Ekosistemine dönüştürülmesi amacıyla hazırlanan teknik inceleme ve uygulama şartnamesi aşağıda istihzar edilmiştir.

İşbu rapor; yazılım mimarisinden bulut donanım kaynaklarına, Apple/Google mağaza regülasyonlarından mevcut 50+ oyun içi kuralın sunucu otoritesine (Server-Authoritative) taşınmasına kadar tüm operasyonel safhaları bağlayıcı hükümlerle tespit etmektedir.

1.2 WebSocket Kanalları ve Veri Tasarrufu (Delta Encoding)

Her 10 saniyede bir binlerce kullanıcıya 75 hissenin tüm verisini göndermek ağ tıkanmasına sebep olacağından, Delta Sıkıştırma Protokolü mecburi kılınmıştır. Yalnızca fiyatı değişen enstrümanlar ikili dizi (tuple) formatında iletilir:

JSON Sinyal Protokolü
// SUNUCU -> İSTEMCİ (Namespace: /market | Room: stocks:all) { "t": 1729331200, // Unix Zaman Damgası "inf": 0.0014, // Anlık Saatlik Enflasyon Katsayısı (%0.14) "s": { // Değişen Hisseler: [Son Fiyat, Yüzde Değişim, Kalan Lot] "ATYR": [145.85, 0.45, 435200], "GOOGL": [2841.10, -0.15, 89100], "TESLO": [682.40, 1.20, 12400] } }

2.1 PostgreSQL Veri Hacmi ve İndeksleme Şartı

100.000 kayıtlı kullanıcı senaryosunda disk hacmi ~2.5 GB, 1.000.000 kullanıcıda ise ~25 GB civarındadır. Darboğazı önlemek üzere aşağıdaki DDL indekslerinin oluşturulması mecburi kılınmıştır:

PostgreSQL 17 DDL İndeksleri
-- Forbes Sıralaması İndeksi (Anlık bakiye taraması için) CREATE INDEX idx_wallet_net_worth ON wallets (cash_balance DESC); -- Portföy ve Lot Sorguları CREATE INDEX idx_holdings_user ON stock_holdings (user_id); CREATE INDEX idx_holdings_stock ON stock_holdings (stock_id); -- Boşta ve Müsait Gayrimenkuller CREATE INDEX idx_property_available ON properties (id) WHERE owner_id IS NULL; -- Aktif Limit Emirleri CREATE INDEX idx_orders_active ON limit_orders (stock_id, type, target_price) WHERE status = 'ACTIVE';

3.1 Sunucu Tarafı Satın Alma Doğrulaması (SSV) Zorunluluğu

Mevcut tek oyunculu sürümde satın alımlar cihaz içinde yerel fonksiyonlarla (grantVIP()) işletilmektedir. Çok oyunculu düzende bu durum ağır bir güvenlik açığı oluşturacağından; mobil istemci faturayı (receipt token) sunucuya iletecek, sunucu Google/Apple uç noktalarıyla el sıkışıp doğrulamayı aldıktan sonra veritabanına bakiye yazacaktır.
